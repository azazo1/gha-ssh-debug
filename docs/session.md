# 会话里的注意事项

Upterm 给的是一个**共享 PTY**, 不是普通 sshd. 下面几条都是因为这个区别.

## 不能 `ssh host '命令'`

远端那个 shell 是会话自己开着的, 不是为你的连接新起的. 所以要把命令**打进已经开着的那个 shell**.
`exec` 和 `run` 都替你做了这件事, 直接用就行:

- 短命令, 要看即时输出: `exec <本地脚本>`
- 长任务 (构建之类): `run <本地脚本>`
- 大文件 (APK/日志): `pull-large <runner 路径> [本地目录]`

`exec` 的输出会去掉 ANSI 颜色/标题/bracketed-paste 序列, 不用再自己 `sed` 清洗. 但共享 PTY
仍会回显命令和 prompt, 读输出时不要假设第一行就是结果.

## 大文件不要用普通 pull

upterm 的 scp 通道在 20MB 以上经常中途断开; 普通 `pull` 可能只落地一部分. `pull-large`
会在 runner 上分块, 逐块核对大小, 合并后核对 sha256, 适合 20MB 以上的 APK, 日志和
构建产物. 默认 20MB 一块, 不要调到很大.

## 连上会先回放整段终端缓冲

所以你看到的输出开头往往是一堆历史内容. `exec` / `run` 的做法是先发一个带时间戳的标记,
再从**最后一次**出现的标记往后截取, 所以你拿到的只有本次的输出.

自己手工用 `ssh` 那条时也要这么做, 否则分不清哪段是新的.

## 长行会被静默截断, 所以脚本要走 scp 上传

终端规范模式对单行输入有长度上限 (macOS 与 Linux 各自量级在 1KB 到 4KB 之间). 一个真实
脚本 base64 之后是一根几 KB 到几十 KB 的**单行**, 正好撞上这个上限, 会被截断或者折行,
于是"脚本传上去了但跑不起来".

所以:

- 脚本一律写成本地文件, 交给 `exec` (逐行喂) 或者 `run` (scp 上传) **不要**自己拼 base64 单行.
- 万一确实要手工传一段内容, 把它切成多行, 每行都短.

## 打完命令不能马上断连接

命令发出去和 shell 真正执行之间有延迟, 断了就没执行. `exec` 默认等 12 秒
(环境变量 `SSH_DEBUG_HOLD_MS` 可调). `run` 走后台任务, 不受这条影响.

## 断开客户端 != 结束会话

关掉本地 ssh 客户端, 会话还活着, 随时可以重连.

但**工作途中不要 `exit` / `Ctrl-D`**: 会话一结束就彻底没了, 只能重开一个 run 从头来.
只有收工的 `done` 才该让会话结束.

## 其他

- 远端 bash 可能开着 history expansion, 不要发 `$!`.
- 日志写文件, 不要刷共享终端 (共享终端刷满了会影响所有人).
- 想交互式操作 (需要真终端的那种), 用 `just ... ssh`, 它把终端直接交给你.
